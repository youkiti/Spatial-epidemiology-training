## 1. 背景と目的

### 1.1 背景

- 疫学の素養がある読者(公衆衛生・臨床疫学を学ぶ大学院生、行政の統計担当者、若手研究者など)向けに、「地図を描くこと」と「空間統計を行うこと」を明確に区別して教える標準的な入門教材が少ない。choropleth map で色を塗るところまでは多くの教材が扱うが、その先の「本当に集まっているのか」を検定する発想(空間自己相関、空間重み行列)は、通常の疫学カリキュラムでは扱われないことが多く、独学の壁になりやすい。
- 特に Local Moran's I(LISA)・Getis-Ord Gi\*・spatial scan statistic(SaTScan)の3手法は、いずれも「地図上のクラスターを見つける」という共通の目的を持ちながら定義が異なるため、初学者が混同しやすい(`docs/memo.md` 635行目以降がまるごとこの整理に費やされている)。
- 日本感染症学会が公開する専門医名簿という具体的なデータを題材にすることで、抽象的な統計手法の学習と、医師偏在という日本の医療政策上の実課題への応用を結びつける。

### 1.2 目的

一定の疫学の素養がある読者が、

1. **記述**(どこで多い? — 累積罹患割合・標準化割合・SIR/SMR・choropleth map)
2. **パターン**(集まっている? — Global Moran's I・LISA・Gi\*・spatial scan statistic)
3. **説明**(なぜそこに多い? — 通常回帰・spatial regression・CAR/BYM)

という3段階の型を、**概念パート(クイズ付き)**と**Rハンズオン(Rmd)**の往復で身につけられる公開教材(Webページ)を提供する。

### 1.3 設計原則

本教材は同一著者のリポジトリ [ai-kotohajime](https://github.com/youkiti/ai-kotohajime)(生成AI活用FDサイト)の設計思想を輸入する。継承する原則は次の4点。

1. **ログ収集ゼロ・サーバ送信ゼロ。** アクセス解析を含む一切のユーザーログを収集しない。クイズの正誤・合否状態は学習者のブラウザの **localStorage のみ**に保存し、サーバには送信しない(GitHub Pages にはバックエンドが存在しないため構造的に担保される)。
2. **保守は運営者一人が Markdown/JSON 編集だけで回る。** クイズ設問は JSON、本文は Markdown で管理し、テキストエディタでの編集のみで更新が完結する構成にする。
3. **教員の手間を増やさない、というより自習完結を前提とする。** ai-kotohajime は「教員がリンクを送るだけ」という二次利用者(教育者)を明示的な対象者に含めていたが、本教材は学習者の自習完結を主とし、教育者向けの割り当て導線は本教材のスコープに含めない(§2 参照。教員向けページを作るかどうかは §9 未決事項)。
4. **記述言語は日本語。**(`docs/memo.md` も日本語であり、これに合わせる)

加えて、本教材固有の設計原則として次を置く。

5. **「地図を描く」と「空間統計」は別物、という区別を教材全体の出発点に置く。** 色を塗っただけでは「本当に集まっている」とは言えない、という区別がすべての章の前提になる(`docs/memo.md` 2節)。
6. **分子だけの地図を作らない。** 専門医数のような分子(count)だけを地図にする誤りは、教材自身が「6. 初学者が注意する5つの落とし穴」で戒める誤りそのもの。人口(分母)と対にした人口10万対専門医数を基本とし、医師偏在の文脈では患者側の需要指標(高齢者割合など)での標準化も検討対象として扱う(`CLAUDE.md`)。
7. **実データにアクセスできなくても教材が成立すること。** 感染症専門医名簿 PDF は将来取得できなくなる可能性があるため、**概念パートおよびRハンズオン⓪①(環境準備・地図→Moran's I→LISA→Gi\*)はシミュレーションデータのみで完走できる**ようにする。実データ(専門医名簿)はハンズオン②(CAR/BYM の実データ節)と③(MAUP の実演)で使用し、他の章をそれに依存させない。実データが持つ制約(未割付・欠測など)は資料ページ `docs/handson/04-case-study.md` で開示する(§4.1 参照)。

## 2. 対象者

- **一次利用者(読者): 疫学の素養がある学習者。** 具体的には、公衆衛生大学院生、臨床疫学を学ぶ医療者、行政・研究機関で保健統計を扱う担当者などを想定する。
- **前提知識**: 累積罹患割合・有病割合・標準化割合・交絡といった疫学の基礎概念は既知として説明を省略する。一方で、**空間統計に固有の概念**(空間自己相関、空間重み行列、MAUP、空間的アウトライヤー)は初出の概念として丁寧に扱う(`CLAUDE.md`)。
- **前提ツール**: Rハンズオンパートは R とごく基本的な RStudio(または R コンソール)操作ができることを前提とする。`sf`/`ggplot2` のようなパッケージの使い方そのものは教えない(§3 非目標)。
- **二次利用者(教育者)は本教材のスコープに含めない。** ai-kotohajime と異なり、「指導者がリンクを送る」運用を前提とした導線(教員向けガイドページ等)は設けない。教材自体は誰でも自習で使える構成であり、結果として教育者が受講者に URL を共有する使い方は妨げないが、それ用のページ・機能を専用に作ることはしない。(**この判断は memo.md / CLAUDE.md に明記がなく、本文書で新たに決定した設計判断**。理由: memo.md・CLAUDE.md のいずれにも FD 文脈(教員が割り当てる運用)への言及がなく、既定の空間疫学入門書と同じく「自習で読む」形が自然なため。教員向け導線が必要になった場合は追って別 issue で検討する。)

## 3. 非目標(やらないこと)

- **SaTScan ソフトウェア本体の操作手順書ではない。** SaTScan の考え方(異常に患者が多い地理的範囲を探索する)は章4で扱うが、SaTScan の GUI 操作手順・パラメータ設定の網羅的な解説は行わない。**今回の公開範囲では概念紹介にとどめる**(決着済み。理由は §9-3)。
- **GIS の一般教科書ではない。** `sf`/`ggplot2`/座標系(CRS)変換などの GIS 一般操作は前提知識として扱い、体系的には教えない。Rハンズオンで最低限必要な操作のみをその場で示す。
- **空間統計の全手法網羅ではない。** カーネル密度推定、地理的加重回帰(GWR)、時空間クラスタリングなど、3段階の型(記述/パターン/説明)に収まらない発展的手法は扱わない([カリキュラム設計](カリキュラム設計.md)で確定する章立て以外は対象外)。
- **医師偏在対策そのものの政策提言ではない。** 専門医名簿を題材にした可視化・分析手法の教材であり、政策的な結論(専門医をどこに何人配置すべきか等)を導く場ではない。
- **専門医個人への言及・評価は行わない。** 名簿は個人名を含むが、教材で扱うのは地域単位に集計した人数・割合のみとし、個人を特定した分析結果は公開しない(`CLAUDE.md`)。
- **認定制度としての修了証明ではない。** ai-kotohajime にある「目録(修了証)」機能を輸入し、章末クイズの合格を条件に、学習者がブラウザ上で氏名を入力して自己申告の記録として発行できるようにする(2026-08-22 決定。§9-2)。第三者が検証する公式な資格・研修修了の証明ではなく、入力した氏名を Canvas に描画して生成するPNG画像であり、認定制度は設けない。実装は issue #73(発行単位は同 issue で確認する)。
- **ログイン・進捗管理・LMS 機能・アクセスログの収集は行わない。**(§1.3 の原則1と同じ)
- **API 連携によるページ内チャット(生成AIとの対話 UI)は作らない。** 静的サイトとして完結させる。

## 4. コンテンツ要件

### 4.1 全体構成

教材は次の2部構成とする(`CLAUDE.md` 「プロジェクトの目的」)。

1. **概念パート**(Web ページ、6章) — 理論・ビジュアル・具体例を*並列に*提示し、各章に自己チェッククイズと章末クイズが紐づく。章立て・クイズ配置の詳細は [カリキュラム設計](カリキュラム設計.md) §2〜§3 で確定する。
2. **Rハンズオン**(Rmd、事前レンダリング済み、本編3本+環境準備) — 同じ概念を R で手を動かして再現する。章立てとの対応は [カリキュラム設計](カリキュラム設計.md) §4 で確定する。あわせて、実データの制約をまとめた資料ページを1本置く(ハンズオンではない。[カリキュラム設計](カリキュラム設計.md) §4.4)。

**架空データと実データの役割分担**(memo.md が「ユーザーに確認する」としていた論点への回答):

- **架空の10市町村データ**(memo.md 末尾で提案されている構成)は**概念導入用**。①地図 → ②Global Moran's I → ③LISA map → ④Gi\* map → ⑤CAR モデル、と手法を一つずつ積み上げて見せる目的に使う。数値が単純で追いやすく、実データの欠測・行政区域変更などのノイズに気を取られずに手法の挙動そのものを理解できることを優先する。
- **感染症専門医名簿(実データ)はケーススタディ用**。当初は「3段階の型を通しで一度、実課題に適用する体験」(ハンズオン④)に使う想定だったが、**統合ハンズオンは公開範囲から外した**。実データはハンズオン②(CAR/BYM の実データ節)と③(MAUP の実演)で使い、データそのものの制約は資料ページ `docs/handson/04-case-study.md` で開示する([カリキュラム設計](カリキュラム設計.md) §4.4)。
- 上記の分担を採用する理由: memo.md の末尾提案(架空データで①〜⑤を通す)をそのまま概念パートの骨格として使いつつ、CLAUDE.md が明記する「分子だけの地図を描かない」「実データにアクセスできなくても動く」という制約は実データ固有の事情(名簿の改訂・入手性)なので、実データはケーススタディという独立した1本のハンズオンに閉じ込めるのが両立させやすい。

### 4.2 ケーススタディの題材

- **データ源**: 日本感染症学会 専門医名簿 PDF(2026-07-01版)。URL: https://www.kansensho.or.jp/uploads/files/senmoni/meibo_260701.pdf
- 名簿は個人名と所属を含むが公開データであり、集計・可視化には問題ない。**リポジトリには加工過程のコード(PDF パース・地域名寄せ・集計スクリプト)、氏名を含まない集計CSV(都道府県別・二次医療圏別・施設単位)、出力される図表を保持し、生データ(PDF そのもの)・氏名を含む中間ファイルはコミットしない。** 集計CSVに施設単位のものが含まれることと、その公開範囲の方針は §5.4 を参照。
- PDF は改訂されうるため、**取得日をファイル名またはメタデータに残す**(例: `meibo_260701_取得日2026-08-18.csv` のような命名、または加工スクリプトの出力にメタデータとして埋め込む)。
- **分子だけの地図を描かない**(§1.3 原則6)。専門医数を地域の人口で割った人口10万対専門医数を基本の指標とする。医師偏在の文脈では、患者側の需要指標(高齢者割合等)での標準化も検討する。
- 個人名は集計処理の中間段階でのみ使用し、公開ページに載せる図表(地図・表)は地域単位の集計値のみとする(§3 非目標)。リポジトリが保持するデータファイル自体の範囲(施設単位の集計CSVを含む)は §5.4 を参照。

### 4.3 クイズ

- クイズエンジンの実装は同一著者のリポジトリ **[ai-kotohajime](https://github.com/youkiti/ai-kotohajime)** の静的 JS クイズエンジン(`docs/assets/js/quiz.js` 等)を**移植する**(issue #3)。四択・一括採点・不正解設問への解説表示という仕様を踏襲する。
- 各章に **自己チェッククイズ**(合否を記録しない、理解確認用)と **章末クイズ**(合否を記録する、正答率での合格判定)を置く。問題数・合格基準は [カリキュラム設計](カリキュラム設計.md) §3 で確定する。
- 作問(選択肢の作り方、断定語・婉曲表現の対称性、正答位置の分散など)は [作問ガイドライン](作問ガイドライン.md) に従う。同文書も ai-kotohajime の作問ガイドラインを輸入・空間統計向けに調整したものである。
- 章末クイズの合格状態(§5.4 参照。localStorage には合格日時のみを保存し、設問ごとの正誤は保存しない)は、修了証(目録)機能(§9-2)の発行判定にも使う(2026-08-22 決定)。発行単位は、概念パート全6章の章末クイズにすべて合格した場合に1枚発行することで確定した(章ごとの発行はしない。issue #73)。

### 4.4 陳腐化対策

- PDF・境界データなど外部データソースの URL・取得日・ハッシュ値を、取得スクリプトまたはメタデータファイルに記録する(隣接リポジトリ [visualize-regional-medical-care-for-2040](https://github.com/youkiti/visualize-regional-medical-care-for-2040) の `doc/DATA_SOURCES.md` に倣う)。
- 各ページに最終更新日を自動表示する(ai-kotohajime の `mkdocs-git-revision-date-localized-plugin` を踏襲)。

## 5. 技術要件

### 5.1 構成

- **ホスティング**: GitHub Pages
- **サイトジェネレータ**: Material for MkDocs(ai-kotohajime と同一。R成果物の事前レンダリングとの相性、既存のクイズエンジン移植のしやすさを理由に採用)
- **公開先**: `https://youkiti.github.io/Spatial-epidemiology-training/`(想定。リポジトリ名がそのまま Pages パスになる)
- **自己チェッククイズ・章末クイズ**: 静的 JS(ブラウザ内完結、設問データはリポジトリ内 JSON。§4.3)
- **配色**: OS/ブラウザの `prefers-color-scheme` に連動したライト/ダーク自動切替(ai-kotohajime を踏襲。手動トグルは設けない)
- **Rハンズオン(Rmd)は事前レンダリングしてコミットし、CI に R を入れない。** `Rscript scripts/render_handson.R` でローカル生成した Markdown・図(PNG)・配布用 `.Rmd` コピーをリポジトリにコミットし(HTML はコミットしない)、MkDocs のビルド(GitHub Actions)は Markdown の変換のみを行う。理由: GitHub Actions のランナーに R 環境と `spdep`/`CARBayes` 等の空間統計パッケージ一式を毎回インストールするのはビルド時間・保守コストの両面で不利であり、Rmd の実行結果は執筆時に確定するもので都度再計算する必要がないため。

### 5.2 地域単位・境界データ

- **地域単位**: 二次医療圏(全国で約330)を**メイン**とし、都道府県(47)でも同じ分析を行う。両方の単位で結果を見せることは、MAUP(地域の区切り方を変えると結果が変わる問題)の実演を兼ねる(`CLAUDE.md` 未決定事項3への回答)。
- **境界データ(ポリゴン)の入手元**: 国土数値情報(国土交通省)の医療圏データ(A38)。隣接リポジトリ [visualize-regional-medical-care-for-2040](https://github.com/youkiti/visualize-regional-medical-care-for-2040) の `doc/DATA_SOURCES.md`(2026-08-04取得)によれば、`A38-20_GML.zip`(医療圏データ 第2.0版・令和2年度、座標系 JGD2011/EPSG:6668)に一次〜三次医療圏のポリゴンが含まれ、二次医療圏は `A38-20_2.*` として同梱される。同リポジトリでは容量(1.13GB)が GitHub の100MB制限を超えるため生データはコミットせず、簡略化した GeoJSON(`iryoken2_A38-20.geojson`、約6.7MB)を成果物として保持している。**本教材でも同じ方針(生データは取得スクリプトで再取得し、簡略化済み GeoJSON のみコミット)を踏襲する候補とする**(最終決定は issue #4 の担当)。

**注意(簡略化 GeoJSON を隣接判定に使うリスク)**: 隣接リポジトリの `doc/DATA_SOURCES.md` は、この簡略化 GeoJSON(二次医療圏コードでディゾルブ、1km²未満の離島除去、Visvalingam加重2%簡略化、座標0.0001度丸め)について「面積計算等の解析には使わず表示専用とする」と明記している。本教材の章2は queen contiguity(ポリゴンの隣接関係)で空間重み行列を作ることが中心であり、簡略化・離島除去・座標丸めは隣接関係そのものを変えうるため、表示専用と位置づけられたポリゴンをそのまま隣接判定に使ってよいかは別途検証が必要である。簡略化前のポリゴンを使うか、簡略化版で隣接関係が保存されるかを確認したうえでどちらを採るかは、issue #4(境界データの整備)の論点として残す。
- 都道府県境界は e-Stat(政府統計の総合窓口)の統計 GIS、または国土数値情報の行政区域データ(N03)を候補とする。
- 令和2年度時点の二次医療圏データのため、感染症専門医名簿(2026-07-01時点)の所属住所と区割りが完全一致しない可能性がある。この突合はケーススタディのハンズオン(未起票)の担当とする。
- ライセンス表示: 国土数値情報はオープンデータ(利用規約に基づく出典表示)。データ利用ページ(§4.4 陳腐化対策と合わせてサイト内に設置)に出典を明記する。

### 5.4 保守性・プライバシー要件

- 運営者が Markdown 編集のみで本文更新完結。クイズ設問は JSON ファイル編集のみで完結(ai-kotohajime を踏襲)。
- push → 自動ビルド・公開(GitHub Actions)。ただし §5.1 の通り R の実行はビルドに含めない。
- アクセス解析を含む一切のユーザーログを収集しない(§1.3 原則1)。
- localStorage に保存するのはクイズの合否状態のみ。修了証(目録)機能(§9-2)では学習者が氏名(またはニックネーム)を入力するが、その文字列は Canvas 描画にのみ使用し、localStorage への保存もサーバへの送信も行わない(ai-kotohajime の `certificate.js` の設計を踏襲。§1.3 原則1と矛盾しない)。
- **施設単位データ(`data/processed/specialists_facility.csv`・`facility_geo_audit.csv`)の公開範囲**: 氏名を含まない集計値として公開リポジトリに保持し続ける(issue #47 で確定、2026-08-21)。名簿自体が公開情報であり、これらのファイルによる集計は公開情報の再掲という整理による。ただし、氏名列が無いことは再識別リスクが無いことと同義ではない(施設名と公開名簿PDFを突合すれば個人単位の推定が可能な場合がある)ため、この注意は定性的な記述にとどめ、再識別リスクを定量化する数値(例: 専門医数が1名の施設の割合)は文書に追加しない方針とする。正本は `data/processed/README.md`「施設単位データの公開範囲と利用上の注意」節と `LICENSE` §3。
