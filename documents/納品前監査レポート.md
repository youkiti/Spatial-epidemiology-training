## 3. 不適合・残存リスク

優先度は、P0=直ちに公開停止、P1=納品前に解消または明示受容、P2=早期修正、P3=改善提案、とする。

### F-01 [P1] 全Rmd再レンダリングが順序依存で失敗する

**事象**

WindowsのUTF-8ロケールを明示して次を実行すると、⓪・①・②は完了するが、③MAUPの`series-a-rollup`チャンクで停止した。

```bat
set LC_ALL=Japanese_Japan.utf8
Rscript scripts/render_handson.R
```

エラーは次の通り。

```text
Error in select():
! unused arguments (area_code, pref_code)
Quitting from 03-maup.Rmd [series-a-rollup]
```

②は`library(CARBayes)`を実行し、CARBayesの依存が`MASS::select`を検索パス上へ載せる。③は`select()`を未修飾で使用しており、同一Rプロセスで②の後に実行すると`dplyr::select`ではなく別の`select`が呼ばれる。`03-maup`だけを単体レンダリングすると`RENDER_HANDSON_OK`まで到達するため、データ欠損ではなくセッション状態の漏洩による順序依存と判断した。

**影響**

- READMEとCLAUDE.mdに記載された全件再生成コマンドが完走しない。
- CIの鮮度検査は既存マニフェストとのハッシュ一致しか見ないため、この不具合を検出できない。
- レンダラーは実行前に既存図を削除するため、途中失敗すると作業ツリーから後続Rmdの図が消えた状態になる。

**推奨対応**

- `03-maup.Rmd`の`select()`等を`dplyr::select()`へ明示する。
- 各Rmdを独立した環境または子Rプロセスで実行し、パッケージ検索パスを共有しない。
- 生成先を一時ディレクトリにし、1本のレンダリングが完了してから成果物を置換する原子的更新へ変更する。
- リリース前ゲートで全件レンダリング、`RENDER_HANDSON_OK`、鮮度検査、生成差分を確認する。

**合格条件**

全件実行が`RENDER_HANDSON_OK`まで到達し、直後の`check_handson_fresh.py`が合格し、意図しない成果物差分・削除がないこと。

### F-02 [P1] データ処理用依存がWindows ARM64で導入できない

**事象**

新規venvへ次を実行したところ失敗した。

```bat
python -X utf8 -m pip install -r requirements-data.txt
```

`pdfplumber`から導入される`pdfminer.six`、さらに`cryptography` 50.0.0がWindows ARM64用wheelを取得できずソースビルドとなり、OpenSSL開発環境を検出できず停止した。

**影響**

- READMEの手順だけでは監査環境でデータ再生成環境を復元できない。
- CIは`requirements-data.txt`を導入しないため、この問題を検出しない。

**推奨対応**

- 対応OS・CPUアーキテクチャ・Python版を明示する。
- サポート対象にWindows ARM64を含める場合は、利用可能なwheelの組み合わせを固定するか、PDF抽出処理を別のoptional環境へ分離する。
- 少なくともUbuntu x64とクライアントの実利用環境でクリーンインストール試験をCIまたはリリース手順に入れる。

### F-04 [P1] ライセンス適用範囲とメタデータに不整合がある

ライセンス自体は、教材をCC BY 4.0、コードをMITとする形で追加された。ただし次の不整合がある。

- READMEは`analysis/`の`.Rmd`全体をMIT対象として読める。
- `LICENSE`は`.Rmd`の「コードチャンク」をMIT対象としているが、同じRmdに含まれる教材本文のライセンスが明示されていない。
- `analysis/DESCRIPTION`には`License`フィールドがなく、説明文には「ライセンス未決定」と残っている。
- GitHub API上のライセンス認識は`Other / NOASSERTION`である。複数ライセンスのため必ずしも異常ではないが、機械的な利用者には適用範囲が伝わりにくい。

**推奨対応**

`.Rmd`を「本文はCC BY 4.0、コードチャンクはMIT」とするのか、ファイル全体をどちらかへ統一するのかを確定し、README・LICENSE・LICENSE-CODE・DESCRIPTIONを一致させる。クライアント納品では著作権者名と帰属表示も確認する。

### F-05 [P1] 施設単位データの説明と再識別リスク評価が不足する

READMEは「氏名を含まない地域単位の集計値だけ」を保持すると説明しているが、実際には次を含む。

- `specialists_facility.csv`: 施設名と専門医数を持つ1,059行
- そのうち専門医数1名の行: 794行
- `facility_geo_audit.csv`: 施設名、人数、割付方法、経緯度等

氏名列は含まないものの、公開名簿と施設名を照合すれば個人を推定できる場合がある。「公開情報由来」「氏名列がない」ことと、再識別リスクがないことは同義ではない。

**推奨対応**

- 施設単位ファイルをクライアント納品・公開リポジトリへ含める必要性を再確認する。
- 必要なら、利用目的、再識別禁止、公開範囲、保持期間を明示する。
- README・要件定義書の「地域単位のみ」という説明を実態へ合わせる。
- クライアントの個人情報・研究倫理・データガバナンス担当による承認を記録する。

## 4. 監査中に確認した重要な挙動

### Rロケール

監査ツールが設定していた`LC_ALL=C.UTF-8`はWindows版Rで無効であり、日本語を含むCSVが1行目で途切れた。`LC_ALL=Japanese_Japan.utf8`を明示すると読み込みは正常化した。これはF-01の`select()`問題とは別である。

Windows向け手順には、Rが実際に利用できるUTF-8ロケールの確認を加えると再現性が上がる。

### Rレンダラーの異常終了コード

`03-maup`単体実行は`RENDER_HANDSON_OK`まで到達したが、既知の`ragg/systemfonts`終了時クラッシュによりプロセス終了コードは`-1073741569`だった。リポジトリの説明どおり、Rレンダリングの成功判定は終了コードだけでなくセンチネルと成果物検査を使う必要がある。

## 5. 監査の限界

次は本監査で完了していない。

- 外部リンク全件の実アクセス。週次workflowはまだ実行履歴がない。
- Playwright/axeによるブラウザE2E・アクセシビリティ実測。監査側ブラウザ接続の初期化エラーによる。
- 生の専門医名簿PDF、医療情報ネット、国土数値情報、e-Statからの全データ再取得。raw/interimを意図的に含めない設計に加え、データ用依存のクリーン導入が失敗したため。
- `gitleaks`等の専用ツールによる全Git履歴スキャン。今回の秘密情報検査は代表パターンのヒューリスティックである。
- 引用論文の全件再読と統計値の独立再検証。リポジトリ内の`引用検証.md`を既存証跡として扱った。
- クライアントの法務・個人情報・アクセシビリティ基準への正式適合判定。
