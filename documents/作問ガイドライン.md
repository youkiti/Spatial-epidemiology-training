## 1. 目的と適用範囲

本文書は、本教材の四択クイズ・自己チェック(概念パート各章の自己チェック3問・章末クイズ、[カリキュラム設計](カリキュラム設計.md) §2〜§3 参照)を作成・改訂する際に従うべき作問原則の**正本**である。輸入元である ai-kotohajime の作問ガイドラインと同様、NBME Item-Writing Guide および Haladyna らの多肢選択問題(MCQ)作成原則に準拠する(書誌情報・原文引用・照合状況は §6)。

対象は全章の章末クイズ・自己チェックのすべてであり、合否判定の有無にかかわらず同一の原則を適用する(輸入元と同じ方針)。クイズ設問データの実ファイル配置(JSON のパス・命名規則)はサイト実装(issue #2)・クイズエンジン移植(issue #3)で確定する。本文書はそれに先立って作問の中身の基準を定めるものであり、ファイルパスに依存しない。

本文書の「機械チェックの閾値」節(§3)は、issue #3 で移植される `scripts/quiz_lint.py` の実装と一字一句整合させる。**閾値を変更する場合は、本文書と lint の両方を同時に改訂すること。**(輸入元と同じ運用規則。§3 冒頭に再掲)

## 2. 原則

以下7原則は輸入元([ai-kotohajime `AI事始-作問ガイドライン.md`](https://github.com/youkiti/ai-kotohajime) §2)と同一であり、原則そのもの・数値閾値は変更していない。例文のみ空間疫学の題材に差し替えた。

### 2.1 長さの統一

全選択肢を同程度の長さ・詳しさにする。目安は**最長/最短比 1.5倍以内**。正答肢が最長になる問題は、ファイル全体の**40%以下**に抑える(正答肢の長さで見分けられてしまうため)。

**悪い例**(正答肢だけ長く説明的):
- ア. 地図の色が濃いから
- イ. Global Moran's I は、各地域の値とその周辺地域の平均的な値との相関を表す指標であり、正の値が大きいほど似た値を持つ地域同士が地理的に近接して分布していることを示す(正答)
- ウ. 人口が多いから
- エ. 集計期間が長いから

**良い例**(誤答肢に具体性を足し、正答肢は簡潔化):
- ア. 各地域の患者数の合計が全国平均を上回っているかどうかを示す指標である
- イ. 各地域の値と周辺地域の値の相関を表し、似た値の地域が近接しているほど大きくなる指標である(正答)
- ウ. 各地域の面積あたりの患者密度が高いかどうかを示す指標である
- エ. 各地域の人口が周辺地域より多いかどうかを示す指標である

### 2.2 断定語・婉曲表現の対称性

「必ず」「一切」「すべて」等の断定語を使うなら、正答肢・誤答肢の双方に同程度の頻度で使う。「〜うる」「〜ことがある」等の婉曲表現を正答肢専用にしない。

**悪い例**(断定語が誤答肢に集中、婉曲表現は正答肢だけ):
- ア. 地域差は必ず人口密度の違いだけが原因である
- イ. 標準化率を使えば地域差は完全に解消される
- ウ. 年齢構成の違いが地域差の一因になりうるため、標準化率で補正して比較する必要がある(正答)
- エ. 地域差は常に医療機関の数だけで説明できる

**良い例**(正答肢も言い切り調にし、誤答肢にも断定語を配分):
- ア. 地域差は年齢構成の違いのみが原因であり、他の要因は一切関与しない
- イ. 標準化率を使えば地域差は技術的に完全に解消される
- ウ. 年齢構成の違いが地域差の一因となるため、標準化率で補正して比較する(正答)
- エ. 地域差は医療機関の数に特有の問題であり、人口構成では生じない

### 2.3 構造の均質性

列挙構造((1)(2)(3)式)・括弧補足・文末表現(体言止め/です・ます等)を全選択肢で揃える。正答肢だけが網羅列挙構造を持たないようにする。

**悪い例**(正答肢だけ列挙構造):
- ア. 患者数の多さだけを確認すればよい
- イ. 地図の色の濃さだけを確認すればよい
- ウ. (1)人口による標準化、(2)空間的自己相関の検定、(3)交絡要因の検討、の3点を確認する(正答)
- エ. Moran's I の符号だけを確認すればよい

**良い例**(正答肢を散文化して構造を揃える):
- ア. 患者数の絶対値だけを確認すればよい
- イ. choropleth map の色の濃淡だけを確認すればよい
- ウ. 人口による標準化、空間的自己相関の検定、交絡要因の検討を順に確認する(正答)
- エ. Moran's I の符号がプラスかどうかだけを確認すればよい

### 2.4 もっともらしい誤答

誤答肢は学習者が実際に持ちがちな誤解(ミスコンセプション)に基づいて作る。荒唐無稽な捨て肢を置かない。ただし**専門家が読めば明確に誤りと判定でき、正答が一意である**ことを損なわない。

**悪い例**(荒唐無稽な誤答):
- ア. 地図の色が赤いほど患者が空を飛んで移動しているため
- イ. 隣接地域の役所が互いに患者数を貸し借りしているため
- ウ. 隣接する地域は年齢構成・医療アクセス・社会経済状況などが類似する傾向があり、それが疾病率の地理的なまとまり(空間的自己相関)として現れるため(正答)
- エ. 統計ソフトが自動的に隣接地域の数値をコピーしているため

**良い例**(実際にありがちな誤解に基づく誤答):
- ア. 単に人口が多い地域ほど患者数も多く見えるだけであり、地理的な関連はない
- イ. 隣接地域の境界線をどう引くかという行政上の都合にすぎない
- ウ. 隣接する地域は年齢構成・医療アクセス・社会経済状況などが類似する傾向があり、それが疾病率の地理的なまとまりとして現れる(正答)
- エ. 都道府県単位で集計すれば、この地理的なまとまりは必ず消える

### 2.5 正答位置の分散

ファイル全体で `answer` インデックス(0〜3)が偏らないようにする。特定の位置(例: 常に2番目)に正答が集中すると、内容を読まずに位置だけで正答率が上がってしまう。

**悪い例**: 10問中6問で `answer` が同じインデックス(例: すべて2)。
**良い例**: 10問の `answer` が `[0,2,1,3,0,1,2,3,1,0]` のように分散し、各インデックスが最低1回は出現する。

### 2.6 消去法耐性(cover-the-options)

選択肢を隠して問題文だけを読んでも、何を問われているかが分かる(=解答の方向性を自分で構成できる)ことを確認する。問題文(幹)が選択肢に依存せず自立していること。

**悪い例**(選択肢がないと何を問われているか分からない): 「次のうち正しいものはどれか。」
**良い例**(幹だけで論点が分かる): 「ある地域の値だけが周囲より突出して高いとき、Getis-Ord Gi\* ではその地域が hot spot と判定されにくい理由として最も適切なのはどれか。」

### 2.7 正答の一意性と解説の整合

選択肢の文言を改修するときは、正答の内容的正しさを維持し、`explanation`(解説)を新しい選択肢の文言と食い違わないよう同時に更新する。解説が改修前の選択肢の言い回しを引きずっていないか、改修のたびに確認する。

## 3. 機械チェック(lint)の閾値

`scripts/quiz_lint.py`(issue #3 で移植)が自動検査する項目と閾値は以下の通り。輸入元の数値をそのまま踏襲し、**本節が正本、lint は実装**であり、閾値を変える場合は両方を同時に改訂する。

言語判定・スキーマは輸入元の設計(日本語版クイズJSONを基本とし、多言語化を行う場合は `.en.json` 等のサフィックスで判定)を踏襲する想定だが、**本教材で多言語化を行うかどうかは未決定**(本教材のスコープでは日本語のみを前提とする。[要件定義書](要件定義書.md) §1.3 原則6)。多言語化する場合は改めてこの節を改訂する。

### S. スキーマ検査(エラー扱い、他の検査より優先表示)
JSONとしてパース可能か。トップレベルに `title`(str)・`passRatio`(数値)・`questions`(list)があるか。各問題に `q`(str)・`choices`(要素4のstrリスト)・`answer`(int 0〜3)・`explanation`(str)があるか。

### L1. 正答肢最長の割合(ファイル単位)
正答肢が**厳密に最長**(他のどの選択肢よりも文字数が多い)である問題数が `max(1, floor(0.4 × 問題数))` を超えたら違反(10問→4問、12問→4問、3問→1問)。

### L2. 正答肢長の比(問題単位)
`len(正答肢) / mean(len(各選択肢))` が **0.8〜1.3** の範囲外なら違反。文字数は `len(str)` で数える。

### L3. 選択肢長の最長/最短比(問題単位)
`max(len(選択肢)) / min(len(選択肢))` が **1.5** を超えたら違反。文字数は `len(str)` で数える。§2.1「最長/最短比1.5倍以内」に対応する。

### W. 断定語・婉曲表現の偏り(ファイル単位)
- 日本語の断定語: `必ず / 一切 / すべて / 全て / 絶対 / 常に / 決して / 完全に / 例外なく / のみ`(単純部分文字列マッチ)
- 日本語の婉曲表現: `ことがある / 場合がある / 可能性 / かもしれない / おそれ / 傾向`
- 違反条件(いずれかを満たせば違反、ファイル単位):
  - 断定語の延べ出現が誤答肢に3回以上 **かつ** 正答肢に0回
  - 婉曲表現の延べ出現が正答肢に3回以上 **かつ** 誤答肢に0回

(英語版の語彙リストは輸入元のまま据え置く。本教材で英語版を作る場合に使用する: 断定語 `always / never / only / all / every / none / completely / entirely / guaranteed?`、婉曲表現 `may / might / can / could / sometimes / often / possible / possibly / tends? / likely`。単語境界・大文字小文字無視の正規表現マッチ)

### P. 正答位置の分散(ファイル単位)
- 問題数8以上: 0〜3の各インデックスが最低1回出現し、かつ最頻インデックスの出現数が `ceil(0.4 × 問題数)` 以下(章末クイズ12問→5)
- 問題数8未満: 最頻インデックスの出現数が `ceil(0.6 × 問題数)` 以下(自己チェック3問→2)

lint は違反なしで終了コード0、違反ありで終了コード1を返す想定。実行方法(issue #3 で移植後):

```bash
python scripts/quiz_lint.py                    # クイズJSON全件
python scripts/quiz_lint.py <path/to/quiz.json>  # 指定ファイルのみ
```

クイズJSONを Claude Code の Edit/Write で編集すると、`scripts/quiz_hook.py`(PostToolUse hook、issue #3 で移植)が自動で lint を実行し、違反があれば結果を会話に注入する運用も輸入元と同様に踏襲する想定。

## 4. 定性チェックリスト(lint では測れない項目)

機械チェックだけでは判定できない項目。改修のたびに人手で確認する。

- [ ] 誤答肢はもっともらしいか(実際にありがちな誤解に基づいているか。荒唐無稽でないか)
- [ ] それでいて誤答肢は専門家が読めば明確に誤りと判定できるか(正答とまぎらわしくなっていないか)
- [ ] 正答は一意か(複数の選択肢が正答になりうる余地がないか)
- [ ] cover-the-options: 選択肢を隠して問題文だけ読んでも解答の方向性を構成できるか
- [ ] 解説(explanation)は選択肢の現在の文言と整合しているか(改修前の言い回しへの言及が残っていないか)
- [ ] (多言語化する場合)日本語版と英語版で、選択肢の順序・正答位置・内容が同期しているか

## 5. 空間統計に固有の作問上の注意

輸入元の作問ガイドラインは生成AIリテラシーという題材に基づいており、空間統計固有の落とし穴には触れていない。本節は本教材で新設する項目であり、[カリキュラム設計](カリキュラム設計.md) §2 の各章、特に章4(★山場)・章6(落とし穴)の作問で必ず参照すること。

### 5.1 「値が高い」と「hot spot」の混同を誤答肢として使う

章4(LISA/Gi\*/SaTScan の違い)の設問では、「ある地域の値が単独で高いこと」と「その地域が hot spot であること(周囲を含めて高いこと)」を混同させる誤答肢を積極的に用意する。これは章4の学習目標そのものであり、実際に学習者が陥りやすい誤解でもあるため、§2.4「もっともらしい誤答」の条件(実際にありがちな誤解に基づく)を満たしやすい。

**設問例**(§2.6 cover-the-options を満たす幹の例):
「周囲の地域はすべて低い値なのに、ある1地域だけが突出して高い値を示すとき、この地域について最も適切な説明はどれか。」
- ア. Getis-Ord Gi\* によって典型的な hot spot として検出される
- イ. Local Moran's I(LISA)では High-Low に分類される空間的アウトライヤーである(正答)
- ウ. Global Moran's I の値が必ず大きく上昇する
- エ. 標準化率を計算し直せばこの高値は自動的に解消される

このとき、正答(イ)を長々と説明せず簡潔にし(§2.1)、誤答(ア)にも「典型的な hot spot として検出される」という具体的な誤解を持たせる(荒唐無稽にしない、§2.4)。

### 5.2 空間重み行列の定義を問う設問

章2(空間重み行列)では、「隣」の定義(queen contiguity・距離閾値)そのものを問う設問に加えて、**定義の選び方によって分析結果が変わりうる**ことを問う設問(章6の事後決定の落とし穴の伏線)を用意する。誤答肢には「隣の定義は分析結果に影響しない」「隣の定義は統計ソフトが自動的に最適なものを選ぶ」といった、初学者が持ちやすい誤解を反映させる。

### 5.3 生態学的誤謬を問う設問

章6では、「地域単位の関連(例: 高齢者割合が高い地域ほど有病率が高い)」を「個人レベルの因果関係(例: 高齢者は有病率が高い)」と直接読み替える誤りを扱う。誤答肢には、地域相関をそのまま個人の因果に敷衍する典型的な誤解(生態学的誤謬)を、もっともらしく、しかし専門家が読めば明確に誤りと分かる形で用意する。正答肢・誤答肢とも「地域相関から言えること/言えないこと」を対比する構造にし、§2.3 の構造の均質性を保つ。

### 5.4 MAUP を問う設問

章6(および[カリキュラム設計](カリキュラム設計.md) ハンズオン③)では、同じ元データを異なる地域単位(都道府県 vs 二次医療圏)で集計すると結果が変わりうることを問う。誤答肢には「地域単位を変えても統計的な結論は変わらない」「地域単位はできるだけ細かくすれば必ず正確になる」といった誤解を用意する。
