# data/geo/

二次医療圏・都道府県の境界データと、二次医療圏の queen contiguity(隣接関係)。
隣リポジトリ [visualize-regional-medical-care-for-2040](https://github.com/youkiti/visualize-regional-medical-care-for-2040)
が生成済みの `data/processed/area_boundaries_R7.geojson`(339区域)・
`data/processed/prefecture_boundaries_R7.geojson`(47都道府県)を入力に、
`scripts/build_geo.R` の出力をそのままコミットしている。

出典・ライセンス・加工内容の詳細は
[documents/DATA_SOURCES.md](../../documents/DATA_SOURCES.md) の
「境界データ・人口データ」節を参照。ここではファイルの中身と、
issue #4 で要求された診断結果の要約のみを記す。

再生成するには:

```bash
"/c/Program Files (x86)/R/R-4.5.2/bin/Rscript.exe" scripts/build_geo.R
```

(`Rscript` は Git Bash の PATH に無いため、フルパスで呼ぶ必要がある。)

## この境界データは「表示専用」であることの明示

隣リポジトリの `doc/DATA_SOURCES.md` は、この境界データについて
「1km²未満の離島リング除去・Visvalingam加重2%簡略化・座標0.0001度(約11m)丸め」
を行い、「面積計算等の解析には使わず表示専用とする」と明記している。
この教材の骨格は空間重み行列(隣接の定義)そのものであるため、
**「この表示専用データで queen contiguity を導いてよいか」を実測で
確かめる必要がある**。`scripts/build_geo.R` はこの診断を実行し、
stdout と `data/geo/adjacency_diagnostics.md`(下記)の両方に出力する。

## ファイル一覧

### `iryoken2.geojson`

二次医療圏境界(339区域、MultiPolygon)。属性は
`area_code, area_name, pref_code, pref_name, boundary_source` に絞ってある
(`area_boundaries_R7.geojson` の属性のうち可視化に必要なものだけを残した)。

- **`area_code`・`pref_code` はゼロ埋め文字列のまま**(issue #4 の既知の罠。
  数値化すると先頭ゼロが落ちる)。
- 339区域のうち7区域(県南・常陸太田ひたちなか・新宮・岩国・周南・宇和島・宮古)
  は入力の時点で `sf::st_is_valid()` が FALSE だったため、
  `sf::st_make_valid()` で修復してから書き出している(詳細は診断2、下記)。
- `area_code` 昇順にソートして書き出しており、決定的な出力になっている。

### `prefecture.geojson`

都道府県境界(47都道府県、MultiPolygon)。属性は入力のまま
(`pref_code, pref_name, boundary_source`)。`pref_code` 昇順にソート済み。

### `adjacency_iryoken2.csv`

列: `area_code, neighbor_code`。二次医療圏境界から
`spdep::poly2nb(..., queen = TRUE)` で導いた queen contiguity。
両方向を書き出している(`data/simulated/lattice_neighbors.csv` と同じ流儀。
例えば `0101,0102` と `0102,0101` の両方が存在する)。
`area_code` 昇順・`neighbor_code` 昇順でソート済み(1,558行)。

### `adjacency_diagnostics.md`

`scripts/build_geo.R` が実行した診断1〜7の全文(下の「診断結果の要約」は
その一部を転記したもの)。

## 診断結果の要約(2026-08-18実行)

詳細・実行ログ全文は `adjacency_diagnostics.md` を参照。

1. **フィーチャ数**: 二次医療圏339件・都道府県47件で期待どおり。
2. **ジオメトリ妥当性**: 二次医療圏339件中7件が `st_is_valid()` で FALSE
   だった(県南・常陸太田ひたちなか・新宮・岩国・周南・宇和島・宮古)。
   `st_make_valid()` で修復し、修復後は全件 TRUE。都道府県47件は元から全件 TRUE。
3. **孤立区域**: 14件。島しょ(東京都)・佐渡・淡路・隠岐・小豆・五島・上五島・
   壱岐・対馬・天草・熊毛・奄美・宮古(沖縄)・八重山。**全件が実在の離島(または
   離島のみで構成される)医療圏で、内陸の区域は含まれていない**。簡略化・
   座標丸めの副作用ではなく、地理的に妥当な孤立と判断できる。
4. **snap 感度テスト**: 座標が0.0001度(約11m)に丸められているにもかかわらず、
   `poly2nb(snap=0)` と `snap=0.0001`(座標丸め幅と同程度)で隣接ペアの集合は
   完全に一致した(1,558件、集合差0件)。**丸めによって生じた隙間で隣接が
   失われている形跡は無い**(mapshaper の簡略化が共有アークを1度だけ処理する
   〔トポロジ保存〕ことと整合する)。本採用の判定はこの `snap=0` と
   `snap=0.0001` の差だけで行い、`snap=0.001`(丸め幅の10倍、約111m)は
   対照条件として別枠で扱う。この対照条件まで snap を緩めると1,562件に増え、
   4件分の差が生じるが、**これは本来隣接していないポリゴンを許容幅で結合して
   しまう過剰結合であり、丸めの影響を示すものではない**。対照条件で差が出た
   ことを理由に本採用の snap を緩めることはしない。以上から本採用は
   `snap=0`(spdep の既定相当。人為的な結合を一切入れない)とした
   (`adjacency_iryoken2.csv` はこの設定の出力。集合差が0件なので、内容は
   `snap=0.0001` を採用していた場合と完全に同一になる)。
5. **隣接数の要約**: 平均 4.596、最小 0(上記14件の孤立区域)、最大 11。
6. **連結成分**: 隣接グラフ(`adjacency_iryoken2.csv`)は**連結していない**
   (連結成分18個)。内訳を実測すると、「北海道・本州・四国・九州がそれぞれ
   独立した成分になる」という素朴な予想は外れる: **本州(34都府県)と四国
   (4県)は250区域からなる1つの連結成分に併合されている**(実測で確認済み)。
   残りは九州(7県、51区域)・北海道(1道、21区域)・沖縄本島側(3区域)がそれぞれ
   独立した成分、および上記の孤立区域14件(サイズ1の成分)。サイズ1の成分は
   診断3の孤立区域14件と一致することを確認済み。**この非連結性(および
   本州・四国の意外な併合)は、章5(空間回帰・CAR/BYM)で必ず問題になる論点
   である**(下記「実ポリゴンとの関係」の節も参照)。

   本州・四国の併合の原因は診断7(ブリッジ検出)で特定できた。**四国と本州を
   繋いでいるエッジは `3301`(岡山県 県南東部)↔`3706`(香川県 東部)の1本
   だけ**であり、除去すると成分1(250区域)は3301側235区域・3706側15区域に
   分かれる(3301側=本州34都府県分、3706側=四国4県分にほぼ対応)。この2区域は
   **座標が完全一致する頂点を11点共有**しており(lon 134.0076〜134.0242 /
   lat 34.4783〜34.5068 付近のリング)、`snap=0`(頂点完全一致のみ)でも
   隣接と判定される。頂点が偶然近づいたのではなく完全一致であるということは、
   mapshaper の dissolve が共有アークを1本として扱う挙動から見て、**入力データの
   トポロジ上で元から辺を共有している**ことを意味する。つまり**この併合は
   簡略化・座標丸めが作った偽の隣接ではなく、入力データのトポロジに元から
   ある隣接**である。瀬戸内海には県境が横切る島が実在するため、地理的に
   妥当な隣接である可能性が高いが、**一次資料(国土数値情報 A38 の元ポリゴン、
   および該当する市区町村の境界)での裏取りはまだ済んでいない**。具体的な
   島名も特定できていない。
7. **ブリッジ(この1本で連結が決まるエッジ)**: 隣接グラフ全体で、除去すると
   連結成分の数が増えるエッジ(ブリッジ)を DFS で機械的に列挙した。ブリッジは
   9件で、うち都道府県をまたぐものは`3301`↔`3706`(岡山県 県南東部↔香川県
   東部、上記6.で扱った本州・四国間のブリッジ)の1件のみ。残り8件は同一
   都道府県内(件数が多くなりうるため詳細は割愛)。都道府県をまたぐ隣接判定の
   うち「その1本が地域全体の連結・非連結を決めている」急所は、実測できた
   範囲ではこの1本だけだった。空間重み行列を扱う教材にとって、どこが急所かを
   機械的に列挙できることを示す診断として有用。

## poly2nb() をサブプロセスで実行している理由(この開発環境固有の罠)

この開発環境では、339区域のジオメトリに対して `spdep::poly2nb()` を呼ぶと、
計算自体は最後まで正しく終わる(結果を取得できる)のに、**Rプロセスの
終了時に異常終了する**(Git Bashからは終了コード127前後で観測される)。
`scripts/verify_simulation.R` が `spdep::mat2listw()` について記録している
「計算は成功するがプロセス終了時にクラッシュする」現象と同種のものだが、
今回は `mat2listw()` ではなく `poly2nb()` 自体がトリガーになっている
(実測で切り分け済み: `st_read`/`st_make_valid` だけなら異常終了しないが、
直後に `poly2nb()` を呼ぶと異常終了する)。`poly2nb()` は隣接をポリゴンから
導くというこの issue の目的そのものであり避けられないため、
**`scripts/build_geo.R` は `poly2nb()` の呼び出しだけを子プロセスの Rscript
に切り出し、結果をCSVに書き出させてから読み戻す**ことで回避している。
子プロセスが終了時に異常終了しても、計算結果は既にディスクに書き出し
済みなので影響しない。

ただし「CSVファイルが存在する」だけでは、書き込み途中でクラッシュして
切り詰められた不完全な隣接リストを見分けられない。このリポジトリでは
隣接リストが教材全体の土台になるため、`scripts/build_geo.R` は子プロセスが
最後に出力する完了マーカー(`child: 完了`)を親プロセスの標準出力に確認し、
無ければ子プロセスのログ全文を添えて exit 1 する(終了コードは上記のとおり
信用しないが、完了マーカーの有無は信用する)。

## 実ポリゴンとの関係(issue #4 完了後)

`data/simulated/lattice_neighbors.csv` の隣接関係は規則格子(lattice)上で
機械的に定義した queen 隣接であり、実際の二次医療圏ポリゴンの隣接関係では
なかった。本ファイル(`adjacency_iryoken2.csv`)は実ポリゴンから計算した
隣接関係であるため、章2〜4(空間重み行列・Global/Local Moran's I・Gi*)の
ハンズオンで `lattice_*.csv` を本データセットに差し替える際の候補になる。
ただし339区域と `lattice_areas.csv` の18行×19列=342地域は件数が一致しない
ため、差し替えには別途の対応表が必要(未着手)。
